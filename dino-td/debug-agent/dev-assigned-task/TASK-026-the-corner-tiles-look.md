# TASK-026 右下角按钮：出现时看得见，灰的看得出
- 状态: done（2、3、4 过；1 金光有、弹大没有 → BUG-024）
- 提交: f3fbc72

## 改了什么
按 TASK-024 的观感改的两条：
- **新命令出现的那一刻**：按钮从 0.7 倍弹到原大，整块亮一下金光，1.4 秒褪掉（`UiKit.come_in`）。
- **用不了的命令明显暗**：底色、图标（灰、暗）、字都暗下去；没饭时"吃饭"角上的 0 是红的。只改了右下角这种方块按钮（卡片上的"升级 / 修理"也是这种按钮，也会跟着变暗）；建造菜单里"还买不起"的卡片不变。

## 要测什么
1. 第一个黄昏火把按钮出现、第一次做好饭吃饭按钮出现：那一刻注意得到吗（眼睛在别处的时候也行吗）；金光会不会太刺眼、太久。
2. 灰的：没饭的"吃饭"、白天的"火把"和能按的"建造"放在一起，一眼分得出哪个能按吗；会不会暗到像坏了。夜里、黄昏的屏幕上也看一眼。
3. 选中一段被咬过的栅栏（"修理"能按）和木头不够时的"升级"（不能按）：卡片上的这两种按钮也分得出。
4. 没有 SCRIPT ERROR；弹出的时候按钮的位置没有跳（旁边的按钮不动）。

## 怎么算过
- 1：注意得到、不刺眼；2、3：一眼分得出、不像坏了；4 如上。
- 请写一两句观感。

## 结果（debug-agent, 2026-09-29，在 f3fbc72 的干净快照上测）

新探针 `probe:corner_look`：第一个黄昏火把按钮出现的那几帧、第一次有饭时吃饭按钮出现的 24 帧（按钮自己的 scale 和 modulate）；正午、黄昏、夜里三个时辰量每个按钮那一块屏幕的亮度；一张被咬了一半的绊弩卡片（修理能按、升级因为骨头不够不能按）。

**1. 出现的那一刻：金光有，弹大没有。**
- 金光：吃饭按钮出现时 modulate 是 (1.54, 1.35, 0.90)，一秒多里慢慢褪回白色 ✔。不刺眼，亮了一档、暖色。
- **没有从 0.7 倍弹到原大**：两个按钮第一帧的 scale 就是 1.00 → [BUG-024](../bug/BUG-024-the-new-tile-does-not-grow-in.md)（容器重排把 scale 压回 1）。
- 火把在第一个黄昏出现时，因为仓库没木头，一出来就是灰的：金光乘在一个暗按钮上，看上去只是"正常亮度一下再变暗"，不太像金光。眼睛在黄昏提示那边的时候，这一下不容易注意到。吃饭按钮出现时是能按的，金光明显。
- 出现的时候"建造"一个像素都没动 ✔。

**2. 灰的：一眼分得出，不像坏了。** [截图](../bug/img/TASK-026-corner-hours.png)

| 时辰 | 吃饭（没饭） | 火把（白天/没木头） | 建造（能按） |
|---|---|---|---|
| 正午 | 0.096 | 0.092 | 0.152 |
| 黄昏 | 0.075 | 0.070 | 0.151 |
| 夜里 | 0.074 | 0.069 | 0.151 |

（屏幕亮度 0～1。）不能按的大约是能按的一半亮；图标变灰、字变暗；吃饭角上的 0 是红的 (0.95, 0.48, 0.38)。夜里也分得清。不像坏了：形状、字都还在，只是暗。

**3. 卡片上的按钮：分得出。** [截图](../bug/img/TASK-026-card-and-corner.png)：绊弩卡片上"升级（2 骨头）"不能按 0.096，"修理（2 石头、1 骨头）"能按 0.150，"拆除"能按 0.131。升级的字是灰的，修理是亮白的。比右下角的差别小一点，但看得出。卡片占着 1、2 键的时候右下角的键位标记收起了 ✔。

**4. 没有 SCRIPT ERROR** ✔；按钮出现时旁边的按钮不跳 ✔。

**观感**：灰得刚好，一眼知道哪个能按，没有"坏了"的感觉，红色的 0 很清楚。金光可以，但少了弹大，出现的那一下还是偏安静；火把第一次出现时本身就是灰的，金光几乎看不出来。修好 BUG-024 以后应该够了。
